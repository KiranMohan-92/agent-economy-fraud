# Analysis Authority Status

**Effective:** 2026-07-10  
**Purpose:** Route readers to the current research-integrity artifacts and prevent legacy
working notes from being treated as validated conclusions.

## Read this first

The repository contains multiple generations of analysis produced before construct,
platform, label, novelty, and source problems were identified. File presence does not imply
current validity.

For research claims, use this order:

1. **`analysis/STATUS.md`** — authority and routing rules.
2. **`GPD/CLAIM-LEDGER.md`** — controlling claim status and maximum allowed wording.
3. **`GPD/PRIMARY-SOURCE-EVIDENCE.md`** — controlling external-source interpretations.
4. **`GPD/analysis/discovery-agentic-fraud-economy-research-hardening.md`** — controlling
   causal model, replacement thesis, regimes, falsifiers, and next experiments.

If another analysis, manuscript passage, project-state entry, code comment, or presentation
conflicts with these artifacts, the four artifacts above control the research interpretation.
Code, preserved data, and reproducible execution remain the authority for exact numerical
outputs; a prose artifact cannot override a failed reproduction.

The source register is point-in-time verified, not a complete source archive. Its per-entry
snapshot and hash fields control reproducibility; entries marked `Not preserved` must be
reverified before publication or claim promotion.

- unbounded “only work” or universal production-system novelty claims.

## Manuscript and code status

- Manuscript files are presentation outputs, not the authority for whether a claim is
  supported.
- Code behavior and preserved data control reproducible numerical facts.
- Numerical claims without a manifest containing revision, data hashes, cohort counts,
  split, seed, command, environment, and output checksum remain exploratory.
- A code test proves the asserted software behavior under the test; it does not validate the
  scientific construct, source label, external transfer, or deployment utility.
- The repository currently has concurrent edits. Before publication, run a full claim-ID,
  metric, citation, and terminology consistency pass on the final tree.

## Update protocol

To promote a legacy result or change a claim:

1. identify the stable `AEF-C*` claim;
2. for AEF-C013, allocate the next `AEF-C013-T###` ID and enter every initiated test in the
   all-results registry before inspecting data or outcomes;
3. satisfy its named falsifier or upgrade gate;
4. preserve the exact data, code, source, and run evidence;
5. update `GPD/PRIMARY-SOURCE-EVIDENCE.md` if external evidence changed;
6. update `GPD/CLAIM-LEDGER.md` with old/new status and allowed wording;
7. update the discovery artifact if the causal model, regime, or decisive experiment changed;
8. only then revise manuscript prose or recommendations.

Until that sequence is completed, the current status and wording ceiling remain in force.
