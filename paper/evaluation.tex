\section{Empirical and Reproducibility Audit}\label{sec:evaluation}

We re-evaluated each empirical stage against five questions: (i) what variable
was observed; (ii) whether every row and event can be reconstructed; (iii)
whether labels represent the stated construct; (iv) whether reported metrics
recompute; and (v) whether model and test evidence are independent.  A stage is
retained as evidence only when all five answers support its claim.

\subsection{Stage 1: withdrawn synthetic benchmark}

The historical report describes both 100,000 ``addresses'' and 100,000
``transactions,'' but the repository contains neither the generator nor the
row-level benchmark.  Its stated confusion matrix is
$TP=9{,}623$, $FN=377$, $FP=2{,}062$, and $TN=87{,}938$.  These values imply
positive-class precision 82.353\%, recall 96.230\%, and F1 88.753\%.
True macro precision, recall, and F1 are 90.963\%, 96.969\%, and 93.692\%,
respectively.  The reported 88.71\% is therefore approximately positive-class
F1, not macro F1.  One confusion matrix cannot reconstruct the claimed
ROC-AUC 0.97, and no latency harness supports the claimed 97\,ms result.
Stage~1 is withdrawn until its exact generator, seed, rows, scores, and timing
harness are released.

\subsection{Stage 2: registry-proxy ranking}

The retained local label artifact contains 665 registry owner/default-wallet
proxies and 1,069 active counterparties, for $N=1{,}734$ addresses.  Registry
association does not establish a current verified agent wallet, live service,
autonomous execution, transaction purpose, or fraud.  Non-registry
counterparties can include people, contracts, routers, exchanges, bots, and
unregistered agents.  We therefore use ``proxy'' and ``unknown counterparty''
throughout.

\paragraph{Independent recomputation.}
For the historical composite and reference threshold $0.09$, we reproduce
ROC-AUC 0.514719 and the proxy/confusion counts $TP=539$, $FP=718$, $FN=126$,
$TN=351$.  Here $FP$ means an unknown counterparty above the reference, not a
verified false alarm.  The individual ranking AUCs are ER 0.515167, NT
0.599050, VF 0.522026, and TC 0.464749.

The post-hoc positive-discrimination weights in
\cref{eq:exploratory_score} give full-sample AUC 0.622281 with a nominal
address-bootstrap 95\% interval $[0.5951,0.6494]$.  Five-fold stratified
cross-fitting of the weighting rule gives pooled out-of-fold AUC 0.612179
(fold mean 0.614406, SD 0.037857); a logistic combiner gives 0.650263.  These
corrected results are provisional until preserved in an immutable end-to-end
run manifest (revision, data hashes, cohort and split, seed, command,
environment, and output checksum); only the historical 0.5147 is reproduced by
the preserved audit artifact.  They are also not clean external estimates: feature hypotheses and negative cleaning
were developed on this population, graph features were computed before
splitting, and random addresses share components and transactions.

When a threshold targeting a nominal 5\% comparison-class rate is selected
inside each training fold, the held-out aggregate is proxy recall 0.0752,
proxy precision 0.4808, F1 0.1300, and unknown-counterparty alert rate 0.0505.
This exercise demonstrates threshold fragility; it does not estimate fraud
recall, false-positive rate, or deployment utility.

\subsection{Event-identity defect}

The historical SQL omitted the ERC-20 event index and the bridge deduplicated
by transaction hash.  In the retained raw CSV, 107,118 rows collapse to 93,579
unique hashes: 13,539 rows (12.64\%) are discarded.  Only 2,913 discarded rows
are exact duplicates.  The other 10,626 are distinct transfer-event tuples,
spread across 8,321 hashes with multiple transfers.  Since one transaction may
emit several legitimate ERC-20 events, transaction hash is not an event key.

The repaired query carries \texttt{evt\_index}; the bridge now deduplicates by
transaction hash plus event index and fails closed when the index is absent.
That code repair does not retroactively validate the existing parquet files or
metrics.  All Stage~2 artifacts must be regenerated from a bounded, immutable
query before a confirmatory result exists.

\subsection{Stage 3: synthetic transaction motifs}

The injection code encodes eight hand-authored transaction motifs derived from
the same feature hypotheses as the score.  It does not simulate control-plane
enumeration, wallet authorization, deception, victim harm, laundering ground
truth, or market manipulation ground truth.  The old address generator also
omitted the injection instance from its hash, causing pseudoreplication: the
artifact has 82 unique injected senders.  Including the instance identifier
produces 689 deterministic sender identities: 10, 10, 5, 150, 10, 8, 440, and
56 for motifs 1--8, respectively.  Every historical Stage~3 score and recall
therefore refers to a stale population.

The real addresses mixed with the motifs have no benign adjudication.  Their
above-threshold fraction is an \emph{unlabeled alert rate}, not an FPR.  The
historical AUC 0.777, ``7/8 chains,'' and associated threshold results are
withdrawn.  A corrected rerun can establish only that the feature code reacts
to particular programmed motifs.  Adversarial robustness would require an
independent red team, held-out generators, realistic histories and benign
automated twins, preregistered thresholds, and sufficient entity-level sample
sizes.

\subsection{What the evidence does and does not show}

The retained evidence shows that one graph feature weakly ranks historical
registry proxies above selected active counterparties in one connected
snapshot, and that the implementation can respond to hand-authored transaction
motifs.  It does not show agent identification, autonomy, fraud detection,
human-versus-agent separation, attack detection, robustness, banking transfer,
or beneficial intervention.

The next empirical release must satisfy all of the following gates:

\begin{enumerate}[leftmargin=2em]
  \item immutable query identifier, time/block cutoff, extraction timestamp,
    schema, event key, inclusion flow, license, and SHA-256 manifest;
  \item current verified wallet and control evidence, with an explicit unknown
    class and post-registration activity window;
  \item independently adjudicated outcome labels for each separate fraud, AML,
    or market-abuse task;
  \item outer temporal or connected-component testing with every learned or
    cleaned step inside training data;
  \item preregistered baselines, metrics, thresholds, capacity constraints,
    uncertainty method, and kill criteria; and
  \item independent reproduction from a clean checkout and external review.
\end{enumerate}
